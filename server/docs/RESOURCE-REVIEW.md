# Server 资源优化记录 · 2026-10-26

首轮本地优化以独立 `margin-host` 工作目录和插件仓库当前未提交的发布能力为输入，将托管应用放入仓库 `server/`。根目录插件入口、包名、市场描述和发布文件白名单保留。没有读取或复制实际 `data/margin.db`，没有重启现有服务，也没有推送或创建 PR。

## 可复现对比

Windows / Node v24.21.0，同一机器、同一脚本依次运行两个独立子进程。每个临时 SQLite 库包含 240 份合成快照，每份正文约 256 KiB，总正文约 60 MiB。概览和个人列表各请求 5 次，取响应中位数；登录期间健康检查取 3 次中位数。峰值为进程 `resourceUsage().maxRSS`，包含测试过程的内存分配峰值；空闲值在建库后显式 GC 再采样。

| 指标 | 原实现 | 优化后 |
| --- | ---: | ---: |
| 空闲 RSS | 68.86 MiB | 69.04 MiB |
| 整段测试峰值 RSS | 304.13 MiB | 103.02 MiB |
| 管理概览响应中位数 | 94.96 ms | 1.37 ms |
| 个人列表响应中位数 | 361.08 ms | 2.36 ms |
| 两个登录计算期间健康检查中位数 | 62.73 ms | 1.00 ms |
| 前端入口 JS，未压缩 | 761,924 B | 122,201 B |
| 入口 + 首页模块 JS，未压缩 | 761,924 B | 204,349 B |
| 合成演示快照的保存大小 | 17,572 B（缩进） | 14,377 B（紧凑） |

这是一次受控本地对比，不是实际线上压力结果；空闲内存没有明显下降，收益集中在读取大量记录和并发登录时。首页代码指标不含其他共享模块、CSS、字体和网络传输开销。首页模块使用 GSAP，阅读器仍需 Markdown、KaTeX 和高亮模块；按路由加载避免登录页和管理页提前获取这些代码。

复现方式（先分别构建两个应用）：

```bash
node --expose-gc server/scripts/benchmark-resources.mjs /path/to/original-margin-host /path/to/repo/server
```

脚本在临时库直接构造元数据性能夹具，不使用生产数据；不能据此证明大快照的发布校验性能。运行后会清理临时库。

另一次只读进程采样中，原服务的 Node 进程工作集约 76 MiB，启动它的 npm 进程约 62 MiB。部署配置直接运行 Node，可去掉 npm 常驻启动层；这个数字受进程状态影响，不承诺固定节省量。

## 已完成的修改

1. 列表查询使用明确的元数据字段，不再把 JSON 正文读进 JavaScript；管理概览的统计、7 日活动和最近 6 条记录交给 SQLite 查询。
2. 新快照使用紧凑 JSON；元数据返回时避免再次从数据库取回刚存入的正文；保留期调整使用一次 SQL 更新，增加会话过期和分享排序索引。
3. 请求密码计算改为异步 scrypt，最多 2 个并发，旧哈希兼容；注册在异步返回后重新检查邀请码、用户名，登录重新确认成员状态。启动引导仍可同步计算一次哈希。
4. 登录/发布限流加入过期清理与键数上限；每个应用独立维护发布窗口；发布在读完请求体后再次检查窗口，避免并发请求穿透节奏限制。
5. 请求体最多 4 个并发，提前检查 Content-Length，中断与超限释放缓存；连接数与读取时间设上限；过期登录会话按批清理。
6. 静态文件元数据查询改为异步，使用流和断开清理；构建时预压缩 Brotli/gzip，提供 ETag/304 与 HEAD。
7. 页面按路由加载，KaTeX 样式随阅读器加载；开发文件监听默认不轮询。
8. 单服务多阶段镜像与 Compose：没有常驻构建工具、没有运行时 npm 依赖、非 root、持久卷、健康检查、日志轮转、资源边界与优雅退出。
9. 修正默认关闭首批邀请码时仍生成 1 个名额的配置错误，以及自动密码的重启提示；不改变已有账号密码。

异步 scrypt 和 HTTP 生命周期处理参考 [Node Crypto](https://nodejs.org/api/crypto.html#cryptoscryptpassword-salt-keylen-options-callback) 与 [Node HTTP](https://nodejs.org/api/http.html)。具体兼容性由本机 Node 24 的回归测试验证。
